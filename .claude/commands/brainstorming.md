description: Brainstorm ideas or approaches for a topic before committing to a plan
---

El usuario quiere hacer brainstorming sobre: $ARGUMENTS

Reglas para esta sesión de brainstorming:

1. No escribas código ni hagas cambios en el repo todavía. Esto es exploración de ideas, no implementación.
2. Si el pedido es ambiguo o falta contexto clave, hacé 1-2 preguntas puntuales antes de tirar ideas al voleo.
3. Generá un rango amplio de opciones (al menos 3-5 cuando tenga sentido), no una sola respuesta obvia. Incluí alternativas poco convencionales, no solo la más segura.
4. Para cada idea, mencioná brevemente el trade-off principal (esfuerzo, riesgo, dependencias, encaje con lo que ya existe en el repo).
5. Si es relevante, mirá el código/estructura actual del proyecto para que las ideas sean realistas y no genéricas.
6. Cerrá con una recomendación clara de por dónde arrancarías vos, pero dejando explícito que es el usuario quien decide.
7. No pases a implementar nada hasta que el usuario elija una dirección explícitamente.
